## What it is

An **iterable** can produce an iterator. An **iterator** returns items through `__next__` and raises `StopIteration` when finished. Every `for` loop uses this protocol.

## Why it exists

One protocol lets lists, files, generators and database cursors all work in the same loop and with the same helpers.

An iterator returns itself from `iter()`, so it can only be consumed once. A list returns a fresh iterator each time.

## Syntax and key APIs

| Built-in | Returns |
| --- | --- |
| `enumerate(xs, start=0)` | `(i, x)` pairs, lazily |
| `zip(a, b, strict=False)` | Tuples, lazily |
| `map(f, xs)`, `filter(f, xs)` | Lazy results |
| `any(xs)`, `all(xs)` | Bool, short-circuits |
| `sum`, `min`, `max` | Consume everything |
| `sorted(xs, key=, reverse=)` | New list |
| `reversed(seq)` | Reverse iterator |
| `next(it, default)` | Item or default |

| itertools | Use |
| --- | --- |
| `chain`, `chain.from_iterable` | Concatenate |
| `islice` | Slice iterators |
| `accumulate` | Running totals |
| `pairwise` | Adjacent pairs |
| `product`, `permutations`, `combinations` | Combinatorics |
| `groupby` | Consecutive groups |
| `count`, `cycle`, `repeat` | Infinite sequences |

## Simple example

```python
it = iter([1, 2])

assert iter(it) is it
assert list(it) == [1, 2]
assert list(it) == []

assert any(x > 1 for x in [1, 2])
assert all(x > 0 for x in [1, 2])
assert next((x for x in [1, 2] if x > 5), "none") == "none"
assert max(["aa", "b"], key=len) == "aa"
assert min([], default=0) == 0
```

## Industry examples

### Detect changes between neighbours

```python
from itertools import pairwise

readings = [10, 12, 11, 15]
assert [b - a for a, b in pairwise(readings)] == [2, -1, 4]
```

### Running totals

```python
from itertools import accumulate
assert list(accumulate([1, 2, 3])) == [1, 3, 6]
assert list(accumulate([3, 1, 2], max)) == [3, 3, 3]
```

### Generate test combinations

```python
from itertools import combinations, product

assert list(product(["GET", "POST"], [200])) == [("GET", 200), ("POST", 200)]
assert list(combinations("abc", 2)) == [("a", "b"), ("a", "c"), ("b", "c")]
```

### Stop early on huge input

`any` stops at the first match, so a generator keeps this cheap.

```python
checked = []

def is_bad(x):
    checked.append(x)
    return x == 2

assert any(is_bad(x) for x in [1, 2, 3, 4])
assert checked == [1, 2]
```

### A custom iterable

```python
class Countdown:
    def __init__(self, start):
        self.start = start

    def __iter__(self):
        return iter(range(self.start, 0, -1))

c = Countdown(2)
assert list(c) == list(c) == [2, 1]
```

## Patterns and best practices

- Pass generator expressions to `any`, `all`, `sum` and `min`.
- Use `next(iterator, default)` for "first match".
- Prefer `zip(strict=True)` when lengths must match.
- Make classes iterable by having `__iter__` return a new iterator.

## Alternatives and trade-offs

| Need | Option | Trade-off |
| --- | --- | --- |
| Several passes | `list` | Memory |
| One pass, large data | Iterator | Single use |
| Heavy numeric work | NumPy | Dependency |

## Common mistakes

**Passing an empty iterable to `max`.** It raises `ValueError`. Use `default=`.

**Iterating a `zip` twice.** It's exhausted after the first.

**`any` on a list comprehension.** The list is fully built first, which loses the short circuit.

**Expecting `sorted` to handle mixed types.** Comparing `int` and `str` raises `TypeError`.

## Interview questions

<Question q="Iterable versus iterator?">
An iterable has `__iter__` and can produce iterators. An iterator has `__next__`, tracks a position and is consumed.
</Question>

<Question q="Why can you loop over a list twice but not a generator?">
A list gives a new iterator on each `iter()` call. A generator is its own iterator.
</Question>

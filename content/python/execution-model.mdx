## What it is

Python is usually described as interpreted, but CPython, the standard implementation, first compiles source code into **bytecode** and then executes that bytecode in a virtual machine.

## Why it exists

Bytecode is portable and quick to start. Compiling once per file and caching the result in `__pycache__` avoids reparsing unchanged modules.

Because names are looked up at run time, a misspelled name in a branch that never runs raises nothing. Top-level statements in a file execute in order, including `def`, which creates a function object when it's reached.

## Syntax and key APIs

| Tool | Purpose |
| --- | --- |
| `python file.py` | Run a script |
| `python -m package` | Run a module as a script |
| `python -i file.py` | Run, then open a prompt |
| `dis.dis(fn)` | Show bytecode |
| `compile(src, name, mode)` | Compile a string |
| `__name__` | `"__main__"` when run directly |

## Simple example

```python
import dis

def add(a, b):
    return a + b

instructions = [i.opname for i in dis.get_instructions(add)]
assert "BINARY_OP" in instructions
assert add.__code__.co_varnames == ("a", "b")
```

## Industry examples

### Guard script-only behaviour

Code at module level runs on import. Put entry-point logic behind a check.

```python
def main():
    return "running"

if __name__ == "__main__":
    assert main() == "running"
```

### Understand late errors

Only executed lines fail at run time, which is why tests need to reach every branch.

```python
def report(flag):
    if flag:
        return undefined_name
    return "ok"

assert report(False) == "ok"

try:
    report(True)
except NameError:
    pass
else:
    raise AssertionError
```

## Patterns and best practices

- Keep module top level free of slow work.
- Run a linter or type checker to catch names that tests miss.
- Use `python -m` so imports resolve from the project root.

## Alternatives and trade-offs

| Runtime | Strength | Trade-off |
| --- | --- | --- |
| CPython | Standard, best ecosystem | Slower for pure Python loops |
| PyPy | JIT speeds long-running code | Extension compatibility varies |
| Cython, C extensions | Native speed for hot code | Build complexity |

## Common mistakes

**Assuming a clean run means no typos.** Untested branches can hide `NameError`.

**Committing `__pycache__`.** It's generated, so ignore it.

**Using a file name like `random.py`.** It shadows the standard module of that name.

## What it is

Control flow decides which statements run and how often. Python uses indentation to define blocks.

## Why it exists

Programs must make decisions and repeat work. Python's `for` loops over any iterable rather than counting indexes, which removes a whole class of off-by-one errors.

## Syntax and key APIs

| Construct | Meaning |
| --- | --- |
| `range(stop)` | 0 up to but excluding stop |
| `range(start, stop, step)` | Lazy arithmetic sequence |
| `break` | Leave the loop |
| `continue` | Skip to the next iteration |
| `x if cond else y` | Conditional expression |
| `while (line := read()):` | Assign and test together |

`match` compares a value against structural patterns.

## Simple example

```python
result = []
for n in range(10, 0, -3):
    if n == 7:
        continue
    result.append(n)

assert result == [10, 4, 1]
assert len(range(10**9)) == 10**9
```

A `range` stores only its start, stop and step, so it uses little memory.

## Industry examples

### Retry with while and else

```python
def connect(attempts):
    tries = 0
    while tries < 3:
        tries += 1
        if attempts[tries - 1]:
            return f"connected after {tries}"
    else:
        return "gave up"

assert connect([False, True, True]) == "connected after 2"
assert connect([False, False, False]) == "gave up"
```

### Dispatch on data shape

```python
def handle(event):
    match event:
        case {"type": "click", "x": x, "y": y}:
            return f"click at {x},{y}"
        case {"type": "key", "code": code} if code < 32:
            return "control key"
        case {"type": str(kind)}:
            return f"other: {kind}"
        case _:
            return "invalid"

assert handle({"type": "click", "x": 1, "y": 2}) == "click at 1,2"
assert handle({"type": "key", "code": 13}) == "control key"
assert handle({"type": "scroll"}) == "other: scroll"
assert handle(5) == "invalid"
```

### Read chunks with the walrus operator

```python
import io

stream = io.BytesIO(b"abcdef")
chunks = []
while chunk := stream.read(4):
    chunks.append(chunk)

assert chunks == [b"abcd", b"ef"]
```

## Patterns and best practices

- Loop over items directly, and use `enumerate` when you need the index.
- Return early to avoid deep nesting.
- Use `any` or `all` instead of a flag variable.
- Comment a loop `else`, since many readers misread it.

## Alternatives and trade-offs

| Need | Option | Trade-off |
| --- | --- | --- |
| Build a list | Comprehension | Single expression only |
| Many branches on one value | `match` or dict dispatch | 3.10+ for `match` |
| Search | `next(..., default)` | Less familiar |

## Common mistakes

**`for i in range(len(xs))`.** Use `for x in xs` or `enumerate`.

**Forgetting a `while` update.** The loop never ends.

**Using `=` in a pattern as a variable by accident.** A bare name in `case name:` captures anything.

**Modifying a list while iterating.** Elements get skipped. Build a new list.

## Interview questions

<Question q="When does a loop's else clause run?">
When the loop finishes without hitting `break`.
</Question>

<Question q="Why is range memory-efficient?">
It's a lazy sequence that computes each value from its start, stop and step.
</Question>

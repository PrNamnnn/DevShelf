## What it is

A list is a mutable, ordered sequence. A tuple is an immutable one. Both hold references to objects of any type.

## Why it exists

Lists suit collections that change. Tuples suit fixed records such as coordinates and can be used as dictionary keys when their contents are hashable.

## How it works

CPython's list is a dynamic array of references. It over-allocates, so `append` is amortized constant time. Inserting or removing at the front shifts every element, so it's linear.

| Operation | Cost |
| --- | --- |
| Index, `append`, `pop()` | Constant (amortized for append) |
| `insert(0, x)`, `pop(0)` | Linear |
| `x in list` | Linear |
| `sort` | O(n log n), stable |

## Syntax and key APIs

```py
xs[start:stop:step]     xs[::-1]        xs[-1]
xs.append(x)            xs.extend(ys)   xs.insert(i, x)
xs.pop()                xs.remove(x)    xs.index(x)     xs.count(x)
xs.sort(key=f)          sorted(xs)      xs.reverse()
first, *rest = xs
```

## Simple example

```python
xs = [0, 1, 2, 3, 4]

assert xs[1:3] == [1, 2]
assert xs[-2:] == [3, 4]
assert xs[::2] == [0, 2, 4]

xs[1:3] = [9]
assert xs == [0, 9, 3, 4]

first, *middle, last = xs
assert (first, middle, last) == (0, [9, 3], 4)
```

## Industry examples

### Named records with NamedTuple

```python
from typing import NamedTuple

class Point(NamedTuple):
    x: float
    y: float = 0.0

p = Point(1.0)
assert p.x == p[0] == 1.0
assert p._replace(y=2.0) == (1.0, 2.0)

locations = {Point(1, 2): "depot"}
assert locations[(1, 2)] == "depot"
```

### Paginate with slices

Slices clip safely, so an out-of-range page is simply empty.

```python
def page(items, number, size):
    start = (number - 1) * size
    return items[start:start + size]

assert page(list(range(5)), 2, 2) == [2, 3]
assert page(list(range(5)), 9, 2) == []
```

### Insert into sorted data

```python
import bisect

scores = [10, 20, 30]
bisect.insort(scores, 25)

assert scores == [10, 20, 25, 30]
assert bisect.bisect_left(scores, 25) == 2
```

## Patterns and best practices

- Prefer tuples for fixed-size records and function returns.
- Use `extend` to add many items and `append` for one.
- Use `sorted` when the original order must survive.
- Use `bisect` to keep a list ordered.

## Alternatives and trade-offs

| Need | Option | Trade-off |
| --- | --- | --- |
| Queue | `deque` | Slow middle access |
| Membership tests | `set` | No order |
| Large numeric data | `array`, NumPy | One element type |

## Common mistakes

**`append` when you meant `extend`.** You get a nested list.

**Assigning `xs = xs.sort()`.** In-place methods return `None`.

**Writing a one-item tuple as `(x)`.** It needs a comma: `(x,)`.

**Assuming tuples are deeply immutable.** A tuple can hold a mutable list.

```python
t = ([1], 2)
t[0].append(2)
assert t == ([1, 2], 2)
```

## Interview questions

<Question q="Why is append amortized O(1)?">
Lists over-allocate capacity, so most appends only write a slot. Occasional resizes copy the array, but their cost averages out.
</Question>

<Question q="List or tuple?">
A list for a changing collection. A tuple for a fixed record, or when you need a hashable sequence.
</Question>

## What it is

Report design arranges visuals so a user can answer known questions quickly.

## Why it exists

Good models fail if users can't read the report. Each extra visual also adds queries and slows a page.

## How it works

Follow a reading pattern: KPI cards on top, main trend next, then breakdowns. Keep slicers in one consistent location. Use tooltips and drill-through for detail instead of adding more visuals.

| Goal | Visual |
| --- | --- |
| Single KPI | Card or KPI |
| Trend | Line |
| Ranking | Bar |
| Cross-tab | Matrix |
| Bridge | Waterfall |
| Driver exploration | Decomposition tree |

## Syntax and key APIs

A theme JSON file centralizes colour and font choices:

```json
{
  "name": "Company",
  "dataColors": ["#2f5fc9", "#bd4573", "#2a8a78"],
  "background": "#ffffff",
  "foreground": "#1a1a1a"
}
```

## Simple example

An executive sales page has four KPI cards, a monthly actual-versus-target line, a region bar chart and a slicer for year. Details move to a separate drill-through page.

## Industry examples

Companies publish standard report templates with fixed themes and navigation, for consistent reading across departments.

## Patterns and best practices

- Design for one audience per page.
- Use comparisons and targets.
- Set alt text and tab order for accessibility.
- Test on the phone layout if needed.

## Alternatives and trade-offs

Paginated reports suit pixel-perfect printing and long tables. Exports to Excel suit ad hoc work but they fragment the source of truth.

## Common mistakes

- Too many visuals per page.
- Slicers everywhere.
- Inconsistent colours for the same entity.
- Reporting without comparison.

## Interview questions

<Question q="How would you redesign a slow, crowded page?">Identify the core question, reduce visuals, move details to drill-through or tooltips and reduce measure complexity.</Question>

<Question q="Report vs dashboard in Power BI?">A report has interactive multi-page visuals based on a model. A dashboard pins tiles to a single page in the service.</Question>

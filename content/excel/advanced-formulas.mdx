## What it is

`LET` assigns names to values within a formula. `LAMBDA` creates custom reusable functions without VBA. Array patterns process entire ranges in one calculation.

## Why it exists

Long formulas repeat sub-expressions, are hard to read and recalculate unnecessarily. `LET` computes a repeated expression once.

## How it works

`LET` takes name-value pairs, up to 126, followed by a final calculation. `LAMBDA` takes parameter names and then a body. It returns `#CALC!` unless called, either directly or via a name defined in the Name Manager. Helpers such as `BYROW`, `BYCOL`, `MAP`, `REDUCE` and `SCAN` apply a `LAMBDA` over arrays.

## Syntax and key APIs

```text
=LET(total,SUM(C2:C6),n,COUNT(C2:C6),total/n)     7.6
=LAMBDA(a,b,a*b)(3,4)                              12
=SUM(BYROW(C2:D3,LAMBDA(r,MAX(r))))
=SUMPRODUCT((A2:A6="North")*C2:C6*D2:D6)
```

Define a reusable function in Name Manager, with the name `MARGIN`:

```text
=LAMBDA(revenue,cost,IF(revenue=0,0,(revenue-cost)/revenue))
```

Then call `=MARGIN(F2,G2)`.

## Simple example

The `SUMPRODUCT` above computes North revenue row by row without a helper column: 10 × 20 + 3 × 150 = 650.

## Industry examples

Modelling teams share `LAMBDA`-based business functions so that a commission or margin rule is defined once. `LET` makes long reporting formulas reviewable.

## Patterns and best practices

- Use descriptive names in `LET`.
- Document named `LAMBDA`s with the Name Manager's comment field.
- Prefer built-in functions when one exists.
- Test edge cases, like empty input and zero denominators.

## Alternatives and trade-offs

VBA handles automation and side effects. Office Scripts suit Excel on the web. Very complex logic is usually clearer in Python or a database.

## Common mistakes

- Variable names that conflict with cell references, like `A1`.
- Calling a `LAMBDA` without arguments.
- Assuming all recipients have the required Excel version.
- Very long nested formulas with no tests.

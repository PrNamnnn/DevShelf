## What it is

Aggregates collapse many rows into one per group. **Window functions** compute across related rows while keeping each row. **CTEs** name a subquery with `WITH`.

## Why it exists

Reports need comparisons like rank in category and running totals. Windows express those without self-joins, and CTEs split complex queries into steps.

## How it works

A window has a partition, an order, and a **frame** of rows relative to the current row.

The default frame with `ORDER BY` is `RANGE UNBOUNDED PRECEDING`, meaning from the partition start through the current row **and its peers**. Without `ORDER BY`, the frame is the whole partition.

## Syntax and key APIs

| Function | Returns |
| --- | --- |
| `row_number()` | Unique sequence |
| `rank()`, `dense_rank()` | Rank, with or without gaps |
| `lag()`, `lead()` | Neighbouring row's value |
| `sum() OVER` | Running or partitioned total |
| `first_value()`, `last_value()` | Value from the frame's edge |

A CTE is inlined into the parent query when it's non-recursive, side-effect-free and referenced once. Use `MATERIALIZED` or `NOT MATERIALIZED` to override.

## Simple example

```sql
CREATE TABLE sales (region text, amount int);
INSERT INTO sales VALUES ('N', 10), ('N', 30), ('S', 20);

SELECT region, sum(amount)::int AS total,
       count(*) FILTER (WHERE amount > 15)::int AS big
FROM sales
GROUP BY region
ORDER BY region;
-- rows: [{"region":"N","total":40,"big":1},{"region":"S","total":20,"big":1}]
```

## Industry examples

### Keep the latest row per customer

```sql
CREATE TABLE events (customer int, seq int, kind text);
INSERT INTO events VALUES (1, 1, 'a'), (1, 2, 'b'), (2, 1, 'c');

SELECT customer, kind FROM (
  SELECT *, row_number() OVER (PARTITION BY customer ORDER BY seq DESC) AS rn
  FROM events
) ranked
WHERE rn = 1
ORDER BY customer;
-- rows: [{"customer":1,"kind":"b"},{"customer":2,"kind":"c"}]
```

### Compare with the previous period

```sql
CREATE TABLE monthly (month int, revenue int);
INSERT INTO monthly VALUES (1, 100), (2, 150);

SELECT month, revenue - lag(revenue) OVER (ORDER BY month) AS change
FROM monthly
ORDER BY month;
-- rows: [{"month":1,"change":null},{"month":2,"change":50}]
```

### Walk a hierarchy

```sql
CREATE TABLE staff (id int, manager int);
INSERT INTO staff VALUES (1, NULL), (2, 1), (3, 2);

WITH RECURSIVE chain AS (
  SELECT id, manager, 1 AS depth FROM staff WHERE id = 3
  UNION ALL
  SELECT s.id, s.manager, c.depth + 1
  FROM staff s JOIN chain c ON s.id = c.manager
)
SELECT max(depth)::int AS levels FROM chain;
-- rows: [{"levels":3}]
```

### A window frame that surprises people

`last_value` with the default frame only sees up to the current row. The docs warn it's likely to give unhelpful results.

```sql
SELECT seq,
  last_value(seq) OVER (ORDER BY seq) AS default_frame,
  last_value(seq) OVER (ORDER BY seq ROWS BETWEEN UNBOUNDED PRECEDING AND UNBOUNDED FOLLOWING) AS whole
FROM (VALUES (1), (2)) AS t(seq)
ORDER BY seq;
-- rows: [{"seq":1,"default_frame":1,"whole":2},{"seq":2,"default_frame":2,"whole":2}]
```

## Patterns and best practices

- Use `row_number()` with a unique `ORDER BY` for repeatable results.
- State the frame explicitly for running totals, using `ROWS`.
- Use `FILTER` instead of `CASE` inside aggregates.
- Use CTEs for readability, and let the planner inline them.

## Alternatives and trade-offs

| Need | Option | Trade-off |
| --- | --- | --- |
| Group summary | `GROUP BY` | Loses detail rows |
| Detail plus summary | Window function | Sorting cost |
| Reused expensive result | `MATERIALIZED` CTE | Blocks predicate pushdown |
| Top N per group | `LATERAL` | Needs an index to shine |

## Common mistakes

**Filtering a window function in `WHERE`.** Windows are computed after `WHERE`. Use a subquery.

**Using `ROWS` with a non-unique order.** The docs say this can produce unpredictable results.

**Recursive CTE without a stopping condition.** It runs until resources run out.

**Assuming CTEs always materialize.** They're usually inlined now.

## Interview questions

<Question q="GROUP BY versus window functions?">
`GROUP BY` returns one row per group. Window functions keep all rows and add calculated values.
</Question>

<Question q="rank versus dense_rank versus row_number?">
`row_number` is always unique. `rank` leaves gaps after ties. `dense_rank` doesn't.
</Question>

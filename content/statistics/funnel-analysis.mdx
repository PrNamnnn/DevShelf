## What it is

A funnel tracks how many users progress through an ordered sequence, such as view → cart → checkout → purchase.

## Why it exists

An overall conversion rate doesn't show where the problem is. Funnels show which step leaks and let you estimate the size of each opportunity.

## How it works

Decide: unit, steps, whether order is strict, conversion window, and whether users can re-enter. **Step conversion** is relative to the previous step. **Overall conversion** is relative to the start. An improvement's impact depends on how much traffic reaches the step, and whether those users are similar to those already converting.

## Intuition and formula

<Formula>overall conversion = step₁ rate · step₂ rate · … · stepₖ rate</Formula>

## Worked example

| Step | Users | Step rate | Overall |
| --- | --- | --- | --- |
| Product view | 10,000 | | 100% |
| Add to cart | 2,500 | 25% | 25% |
| Checkout | 1,000 | 40% | 10% |
| Purchase | 700 | 70% | 7% |

Add-to-cart has the lowest step rate, but raising checkout completion from 70% to 80% is worth 100 additional orders, and could be easier. Both candidates should be sized and considered.

## Python

```python
import pandas as pd

users = pd.Series({"view": 10_000, "cart": 2_500, "checkout": 1_000, "purchase": 700})
step = users / users.shift(1)
overall = users / users.iloc[0]

assert round(step["checkout"], 2) == 0.40
assert round(overall["purchase"], 2) == 0.07
assert round(1_000 * 0.8 - 700) == 100
```

## SQL

```sql
WITH e(user_id, step, at_time) AS (
  VALUES (1, 'view', 1), (1, 'cart', 2), (1, 'buy', 3),
         (2, 'view', 1), (2, 'buy', 2),
         (3, 'cart', 1), (3, 'view', 2)
), t AS (
  SELECT user_id,
         min(at_time) FILTER (WHERE step = 'view') AS v,
         min(at_time) FILTER (WHERE step = 'cart') AS c,
         min(at_time) FILTER (WHERE step = 'buy') AS b
  FROM e GROUP BY user_id
)
SELECT count(v) AS viewed, count(*) FILTER (WHERE c > v) AS carted,
       count(*) FILTER (WHERE b > c AND c > v) AS bought
FROM t;
-- rows: [{"viewed":3,"carted":1,"bought":1}]
```

Requiring timestamps in order excludes users who skip a step or act in the wrong sequence.

## Excel or Power BI

Excel has a Funnel chart under Insert. Power BI includes a Funnel visual, and each step should be a measure applying the same user population.

## In industry

Teams build funnels per platform and acquisition source, and use them as a starting point for experiments.

## Assumptions and limitations

Funnels suggest where, not why. Real journeys aren't linear, and conversion windows affect comparisons.

## Common mistakes

- Counting events rather than users.
- Ignoring order.
- Comparing funnels with different windows.
- Assuming a drop-off is fixable without researching why.

## Alternatives

Path analysis shows actual sequences, and survival models capture time between steps.

## Interview questions

<Question q="Which step should you fix first?">Estimate each step's potential by traffic, plausible improvement and effort. The lowest conversion isn't automatically the best opportunity.</Question>

<Question q="How would you write a funnel in SQL?">Get the first timestamp of each step per user, then count those with correctly ordered timestamps.</Question>

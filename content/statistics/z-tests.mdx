## What it is

A z-test compares a statistic to a null value using the standard normal distribution.

| Test | Question | H₀ |
| --- | --- | --- |
| One-sample | Does this mean differ from a known value? | μ = μ₀ |
| Two-sample | Do two means differ? | μ₁ = μ₂ |
| Two-proportion | Do two rates differ? | p₁ = p₂ |

## Why it exists

Conversion rates are means of 0s and 1s, so with enough observations the normal approximation works well. This is the standard analysis of a binary A/B metric.

## How it works

**When to use:** large samples. A one-sample or two-sample z-test for means requires σ to be known, which is rare, so a t-test is usually used instead. **Data type:** binary or numeric. **Assumptions:** independent observations, and at least about 10 successes and 10 failures per group for proportions.

**H₁:** the parameter differs from the null, or for a directional test, lies on one side.

**Interpreting the p-value:** it's the chance of a result this extreme with no real difference.

**Business meaning:** always translate the difference into incremental conversions or revenue.

## Intuition and formula

<Formula>z = (x̄ − μ₀) / (σ / √n)</Formula>

<Formula>z = (p̂₂ − p̂₁) / √(p̄(1 − p̄)(1/n₁ + 1/n₂))</Formula>

p̄ is the pooled rate, used because the null says both rates are equal.

## Worked example

Control has 520 conversions of 10,000 (5.2%), and treatment has 580 of 10,000 (5.8%). The pooled rate is 5.5%. Then z = 1.86 and the two-sided p-value is 0.063, so at α = 0.05 we don't reject H₀. The difference is +0.6 points with a 95% CI of about −0.03 to +1.23 points. The honest conclusion is that the test is inconclusive, because a meaningful lift is plausible, and so is none.

A one-sample example: a call center's mean duration is 1000 seconds with a known σ of 120. A sample of 64 averages 1040, so z = 40 ÷ 15 = 2.67, p = 0.0077.

## Python

```python
import numpy as np
from scipy import stats
from statsmodels.stats.proportion import proportions_ztest

z, p = proportions_ztest([580, 520], [10_000, 10_000])
assert (round(z, 2), round(p, 3)) == (1.86, 0.063)

diff = 0.058 - 0.052
se = np.sqrt(0.058 * 0.942 / 10_000 + 0.052 * 0.948 / 10_000)
assert round(diff - 1.96 * se, 4) == -0.0003
assert round(diff + 1.96 * se, 4) == 0.0123

z1 = (1040 - 1000) / (120 / np.sqrt(64))
assert round(2 * stats.norm.sf(z1), 4) == 0.0077
```

## SQL

```sql
WITH s AS (SELECT 520.0 AS a, 10000.0 AS na, 580.0 AS b, 10000.0 AS nb),
     p AS (SELECT *, (a + b) / (na + nb) AS pooled FROM s)
SELECT round((b / nb - a / na) / sqrt(pooled * (1 - pooled) * (1 / na + 1 / nb)), 2) AS z
FROM p;
-- rows: [{"z":"1.86"}]
```

## Excel or Power BI

Compute z in a cell, then `=2*(1-NORM.S.DIST(ABS(z),TRUE))`. Excel's `Z.TEST` is a one-tailed one-sample test and is easy to misuse.

## In industry

Experimentation platforms run this calculation at scale for each binary metric, with corrections for peeking and multiple metrics applied.

## Assumptions and limitations

Observations must be independent, so randomize and analyze at the same unit. Very small rates need far larger samples for the approximation to hold.

## Common mistakes

- Analyzing conversion per session when users were randomized.
- Using a z-test for means with an estimated SD at small n.
- Using the pooled standard error for a confidence interval. Use the unpooled form.
- Reporting relative lift only, hiding small absolute differences.

## Alternatives

Fisher's exact test handles very small counts. A chi-square test on a 2×2 table without continuity correction is mathematically equivalent to the two-sided two-proportion z-test, since χ² = z². Logistic regression adds covariates.

## Interview questions

<Question q="Why pool the proportions in the test statistic?">Because the null hypothesis says they're equal, so the best estimate of the shared rate under H₀ uses both groups.</Question>

<Question q="How does the two-proportion z-test relate to chi-square?">For a 2×2 table without continuity correction, the chi-square statistic equals z² and the two-sided p-values match.</Question>

## What it is

The `OVER` clause partitions and orders a rowset before a window function applies, keeping every row. A CTE names a query for use in the next statement.

## Why it exists

Reports constantly need rank, previous value or running total. Window functions replace slow self-joins and cursors.

## How it works

Window functions run after `WHERE` and `GROUP BY`, near the end of the query. For best performance, an index should have the `PARTITION BY` columns followed by the `ORDER BY` columns.

A CTE exists only for the single statement that follows it. Unlike PostgreSQL's optional materialization, it's expanded into the query, so referencing it twice evaluates it twice.

## Syntax and key APIs

```plsql
ROW_NUMBER() OVER (PARTITION BY a ORDER BY b)
SUM(x) OVER (ORDER BY d ROWS UNBOUNDED PRECEDING)
LAG(x, 1, 0) OVER (ORDER BY d)
```

## Simple example

```sql
CREATE TABLE #sales (region char(1), amount int);
INSERT #sales VALUES ('N', 30), ('N', 10), ('S', 20);

SELECT region, amount,
       ROW_NUMBER() OVER (PARTITION BY region ORDER BY amount DESC) AS rn
FROM #sales
ORDER BY region, rn;
-- output: N|30|1
-- output: N|10|2
-- output: S|20|1
```

## Industry examples

### Delete duplicates, keeping one

```sql
CREATE TABLE #contacts (id int IDENTITY, email varchar(50));
INSERT #contacts (email) VALUES ('a@x.io'), ('a@x.io'), ('b@x.io');

WITH ranked AS (
  SELECT *, ROW_NUMBER() OVER (PARTITION BY email ORDER BY id) AS rn FROM #contacts
)
DELETE FROM ranked WHERE rn > 1;

SELECT COUNT(*) FROM #contacts;
-- output: 2
```

### Running balance

Specify `ROWS`, because the default frame with `ORDER BY` is `RANGE`, which includes peers.

```sql
CREATE TABLE #ledger (d int, amount int);
INSERT #ledger VALUES (1, 10), (2, 20), (3, -5);

SELECT d, SUM(amount) OVER (ORDER BY d ROWS UNBOUNDED PRECEDING) AS balance
FROM #ledger
ORDER BY d;
-- output: 1|10
-- output: 2|30
-- output: 3|25
```

### Find streaks

```sql
CREATE TABLE #logins (d int);
INSERT #logins VALUES (1), (2), (3), (7), (8);

WITH g AS (
  SELECT d, d - ROW_NUMBER() OVER (ORDER BY d) AS grp FROM #logins
)
SELECT MIN(d), MAX(d) FROM g GROUP BY grp ORDER BY MIN(d);
-- output: 1|3
-- output: 7|8
```

### Walk an org chart

`MAXRECURSION` defaults to 100.

```sql
CREATE TABLE #staff (id int, manager int);
INSERT #staff VALUES (1, NULL), (2, 1), (3, 2);

WITH chain AS (
  SELECT id, manager, 1 AS depth FROM #staff WHERE id = 3
  UNION ALL
  SELECT s.id, s.manager, c.depth + 1
  FROM #staff s JOIN chain c ON s.id = c.manager
)
SELECT MAX(depth) FROM chain OPTION (MAXRECURSION 10);
-- output: 3
```

## Patterns and best practices

- Create a supporting index on partition then order columns.
- Use a unique `ORDER BY` for repeatable numbering.
- State frames explicitly with `ROWS`.
- Terminate the previous statement with `;` before `WITH`.

## Alternatives and trade-offs

| Need | Option | Trade-off |
| --- | --- | --- |
| Reusable within one statement | CTE | Re-evaluated on each reference |
| Reuse across statements | Temp table | More steps, gets statistics |
| Per-group top row | `APPLY` | Best with an index |

## Common mistakes

**Using a window function in `WHERE`.** Wrap it in a CTE or subquery first.

**Assuming CTEs improve performance.** They're mainly for readability.

**Forgetting `ORDER BY` in the outer query.** A window's order doesn't determine the output order.

**Relying on the default `RANGE` frame for running totals.** It's slower and treats ties as one.

## Interview questions

<Question q="How would you remove duplicates?">
Number rows within each duplicate key with `ROW_NUMBER` in a CTE, and delete those with a number above 1.
</Question>

<Question q="CTE or temp table?">
A CTE for readability within one statement. A temp table for reuse or when the optimizer benefits from statistics on an intermediate result.
</Question>

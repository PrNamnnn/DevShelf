## What it is

The **clustered index** stores a table's rows in key order, and there can be only one. A **nonclustered index** is a separate structure holding a subset of columns and a pointer back to the row.

## Why it exists

Microsoft's guidance is that, with few exceptions, every table should have a clustered index. Nonclustered indexes then make specific queries fast by reading far fewer pages.

## How it works

On a clustered table, a nonclustered index's row locator is the **clustered key**. If a query needs columns the index doesn't have, SQL Server performs a **key lookup** into the clustered index for each row.

A good clustered key is narrow, unique, ever-increasing and immutable. Key columns are limited to 16 and 900 bytes.

## Syntax and key APIs

```sql
CREATE TABLE #orders (
  id int NOT NULL PRIMARY KEY CLUSTERED,
  customer_id int NOT NULL,
  status varchar(10) NOT NULL,
  total decimal(10,2) NOT NULL
);

CREATE NONCLUSTERED INDEX ix_customer ON #orders (customer_id) INCLUDE (total);
CREATE NONCLUSTERED INDEX ix_failed ON #orders (customer_id) WHERE status = 'failed';
```

In SSMS, use **Query, Include Actual Execution Plan**. For I/O:

```plsql
SET STATISTICS IO ON;
```

**Logical reads** are pages read from cache, and are the most stable measure to compare.

## Simple example

The scan, lookup and covering numbers in the diagram came from this shape of query.

```sql
INSERT #orders VALUES (1, 42, 'paid', 9.99), (2, 7, 'failed', 5.00);

SELECT id, total FROM #orders WHERE customer_id = 42;
-- output: 1|9.99
```

The plan for the version needing a lookup, from the 200,000-row test:

```text
Nested Loops(Inner Join, OUTER REFERENCES:([#orders].[id]))
  Index Seek(... SEEK:([#orders].[customer_id]=(42)) ORDERED FORWARD)
  Clustered Index Seek(... SEEK:([#orders].[id]=[#orders].[id]) LOOKUP ORDERED FORWARD)
```

## Industry examples

### Cover a frequent query

Put filter and join columns in the key, and returned columns in `INCLUDE`, where they don't affect the key size limit.

```plsql
CREATE INDEX ix_orders_customer ON dbo.Orders (CustomerId, CreatedAt DESC)
INCLUDE (Total, Status);
```

### Index a small subset

Filtered indexes support simple comparison predicates. Keep conversions off the left side of the filter.

```plsql
CREATE INDEX ix_open ON dbo.Orders (CreatedAt) WHERE Status = 'open';
```

### Keep predicates SARGable

A function or calculation on the column prevents a seek. In the test, `customer_id + 0 = 42` became an **Index Scan**.

```plsql
-- Scan:
WHERE YEAR(CreatedAt) = 2026

-- Seek:
WHERE CreatedAt >= '2026-01-01' AND CreatedAt < '2027-01-01'
```

## Patterns and best practices

- Choose a clustered key that's narrow and unique.
- Add `INCLUDE` for frequently returned columns only.
- Check for implicit conversions in plans, especially `nvarchar` against `varchar`.
- Compare logical reads before and after a change.

## Alternatives and trade-offs

| Option | Benefit | Cost |
| --- | --- | --- |
| Key lookup | Smaller index | Cost grows per row |
| Covering index | Fewest reads | Larger, slower writes |
| Filtered index | Tiny, focused | Limited predicates |
| Columnstore | Analytics | Not for point lookups |

## Common mistakes

**A wide clustered key.** It's copied into every nonclustered index.

**Clustering on a random GUID.** New rows land throughout the index and cause page splits.

**Adding every missing-index suggestion.** They overlap and increase write costs.

**Putting non-filter columns in the key.** Use `INCLUDE` instead.

**Creating a filtered index from `sqlcmd` without `-I`.** `sqlcmd` defaults `QUOTED_IDENTIFIER` to off, and the statement fails with error 1934. SSMS has it on.

## Interview questions

<Question q="Clustered versus nonclustered?">
A clustered index is the table's row storage, sorted by key. A nonclustered index is a separate structure pointing back to the rows.
</Question>

<Question q="What is a key lookup?">
A fetch from the clustered index for columns missing from the nonclustered index. Including those columns removes it.
</Question>

<Question q="What does SARGable mean?">
A predicate that can use an index seek, typically because the indexed column isn't wrapped in a function or expression.
</Question>

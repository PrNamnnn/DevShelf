## What it is

Each component instance goes through creation, mounting, updating and unmounting. Lifecycle hooks register code to run at those points.

## Why it exists

Some work needs the real DOM, such as measuring an element. Other work needs teardown, such as removing a listener.

Hooks must register synchronously during `setup`. A call inside `setTimeout` won't work.

## Syntax and key APIs

| Hook | Use |
| --- | --- |
| `onMounted` | DOM access, starting subscriptions |
| `onUpdated` | Reacting to any DOM change |
| `onUnmounted` | Cleanup |
| `onErrorCaptured(err, instance, info)` | Catch descendant errors |
| `onActivated`, `onDeactivated` | `KeepAlive` caching |
| `nextTick()` | Wait for the next DOM update |

## Simple example

```js
import assert from "node:assert";
import { JSDOM } from "jsdom";

const { window } = new JSDOM(`<div id="app"></div>`);
Object.assign(globalThis, { window, document: window.document, Element: window.Element, SVGElement: window.SVGElement, Node: window.Node });
Object.defineProperty(globalThis, "navigator", { value: window.navigator, configurable: true });

const { createApp, h, onMounted, onUnmounted } = await import("vue");
const log = [];

const app = createApp({
  setup() {
    log.push("setup");
    onMounted(() => log.push("mounted"));
    onUnmounted(() => log.push("unmounted"));
    return () => h("p", "hi");
  },
});

app.mount(document.querySelector("#app"));
app.unmount();

assert.deepEqual(log, ["setup", "mounted", "unmounted"]);
```

## Industry examples

### Clean up global listeners

```vue
<script setup>
import { onMounted, onUnmounted, ref } from "vue";

const width = ref(0);
const update = () => (width.value = window.innerWidth);

onMounted(() => {
  update();
  window.addEventListener("resize", update);
});
onUnmounted(() => window.removeEventListener("resize", update));
</script>
```

### Read the DOM after a state change

```vue
<script setup>
import { nextTick, ref, useTemplateRef } from "vue";

const open = ref(false);
const input = useTemplateRef("field");

async function show() {
  open.value = true;
  await nextTick();
  input.value.focus();
}
</script>

<template>
  <input v-if="open" ref="field" />
</template>
```

### Report errors from a subtree

```vue
<script setup>
import { onErrorCaptured, ref } from "vue";

const failed = ref(false);
onErrorCaptured((error) => {
  report(error);
  failed.value = true;
  return false;
});
</script>
```

## Patterns and best practices

- Pair every subscription with cleanup.
- Prefer watchers to `onUpdated` for reacting to specific data.
- Put reusable lifecycle logic in composables.
- Remember `onMounted` doesn't run during server rendering.

## Alternatives and trade-offs

| Need | Option | Trade-off |
| --- | --- | --- |
| React to specific data | `watch` | Doesn't guarantee DOM state |
| After DOM update | `nextTick` | One-off |
| Any re-render | `onUpdated` | Runs often |

## Common mistakes

**Registering a hook after `await`.** It can lose its instance.

**Mutating state in `onUpdated`.** That can cause an infinite update loop.

**Touching `window` in `setup` with SSR.** Move it to `onMounted`.

**Not returning `false` from `onErrorCaptured` when handling.** The error continues upward.

## Interview questions

<Question q="When can you access the DOM?">
From `onMounted` onward, or after `await nextTick()` following a state change.
</Question>

<Question q="Which hooks run during server rendering?">
`setup` runs. `onBeforeMount` and `onMounted` don't.
</Question>

## What it is

Vue's reactivity system records which effects read which data, then re-runs exactly those effects when the data changes.

## Why it exists

You write ordinary-looking code that reads state. Vue works out the dependencies at runtime, so you don't have to list what each piece of UI depends on.

## How it works

`ref` uses getter and setter functions on `.value`, while `reactive` uses a JavaScript `Proxy`. Reads call `track`, and writes call `trigger`. Subscribers are stored in a global `WeakMap<target, Map<key, Set<effect>>>`.

DOM updates are buffered until the next tick so that many changes cause one update. `await nextTick()` waits for that update.

## Syntax and key APIs

| API | Use | Note |
| --- | --- | --- |
| `ref(v)` | Any value | Access through `.value` |
| `reactive(obj)` | Objects only | Returns a proxy |
| `shallowRef(v)` | Large immutable data | Only `.value` access is tracked |
| `toRefs(obj)` | Destructure reactive objects | Keeps the link |
| `toRaw`, `markRaw` | Escape reactivity | Use sparingly |
| `nextTick()` | Wait for the DOM update | Returns a promise |

## Simple example

```js
import assert from "node:assert";
import { reactive, ref, watchEffect } from "vue";

const count = ref(1);
const state = reactive({ total: 0 });

watchEffect(() => {
  state.total = count.value * 2;
}, { flush: "sync" });

count.value = 3;
assert.equal(state.total, 6);
```

## Industry examples

### Avoid deep tracking for big payloads

```js
import assert from "node:assert";
import { shallowRef, watchEffect } from "vue";

const rows = shallowRef([{ id: 1 }]);
let runs = 0;

watchEffect(() => {
  rows.value.length;
  runs++;
}, { flush: "sync" });

rows.value.push({ id: 2 });
assert.equal(runs, 1);

rows.value = [...rows.value];
assert.equal(runs, 2);
```

### Keep reactivity through destructuring

```js
import assert from "node:assert";
import { reactive, toRefs } from "vue";

const state = reactive({ count: 0 });

const { count: lost } = state;
const { count } = toRefs(state);

state.count = 5;
assert.equal(lost, 0);
assert.equal(count.value, 5);
```

## Patterns and best practices

- Default to `ref`, which works for any type and survives reassignment.
- Replace `shallowRef` values instead of mutating them.
- Keep reads inside the effect's synchronous part.
- Compare proxies consistently: `reactive(raw) !== raw`.

## Alternatives and trade-offs

| Option | Good for | Trade-off |
| --- | --- | --- |
| `ref` | Default | `.value` in script |
| `reactive` | Grouped state | Can't be replaced or destructured safely |
| `shallowRef` | Large or external objects | Inner changes aren't tracked |

## Common mistakes

**Replacing a `reactive` object.** The old proxy's subscribers aren't transferred.

**Destructuring reactive state.** It copies the primitive and loses the connection.

**Expecting refs to unwrap in arrays.** Ref elements in arrays and `Map`s need `.value`.

```js
import assert from "node:assert";
import { reactive, ref } from "vue";

const books = reactive([ref("Vue")]);
assert.equal(books[0].value, "Vue");

const object = reactive({ count: ref(1) });
assert.equal(object.count, 1);
```

**Reading the DOM right after changing state.** Wait for `nextTick`.

## Interview questions

<Question q="How does Vue know what to update?">
While an effect runs, each reactive read registers the effect as a subscriber. A later write triggers those subscribers.
</Question>

<Question q="Why does Vue use Proxy instead of getters and setters on objects?">
Vue 3 uses `Proxy` for reactive objects, while `ref` uses getters and setters for `.value`. Vue 2 relied only on getters and setters.
</Question>

<Question q="When would you use shallowRef?">
For large data structures or external objects, where deep tracking is expensive and you can replace the value instead of mutating it.
</Question>

## What it is

Structured output constrains a model to return data that matches a schema, so your code receives an object rather than text to parse.

## Why it exists

Applications need fields they can trust: a category, a date, a list of items. Prompting for JSON alone is unreliable.

## How it works

There are two main strategies.

| Strategy | Mechanism | Notes |
| --- | --- | --- |
| `ProviderStrategy` | The provider enforces a schema natively | Needs model support |
| `ToolStrategy` | The schema is presented as a tool the model must call | Works with any tool-calling model |

Passing a schema type to `create_agent` lets LangChain pick automatically: provider-native when supported, tool-based otherwise. A JSON Schema dictionary has to be wrapped in an explicit strategy. The result appears in `result["structured_response"]`.

## Syntax and key APIs

```py
from langchain.agents.structured_output import ProviderStrategy, ToolStrategy

structured = model.with_structured_output(Invoice)
invoice = structured.invoke("...")

agent = create_agent(model, tools=[], response_format=ToolStrategy(Invoice))
```

<Callout type="deprecated">
Prompted output with `response_format=("prompt", Schema)` was removed in v1. Use a strategy.
</Callout>

## Simple example

Validation is what makes the output trustworthy.

```python
from pydantic import BaseModel, Field, ValidationError

class Review(BaseModel):
    """A product review."""
    score: int = Field(ge=0, le=5)
    summary: str

assert Review(score=4, summary="good").score == 4

try:
    Review(score=12, summary="too high")
except ValidationError as error:
    assert error.errors()[0]["loc"] == ("score",)
else:
    raise AssertionError
```

## Industry examples

### An agent returning a typed result

This runs the real agent with a scripted model that "calls" the schema tool.

```python
from langchain.agents import create_agent
from langchain.agents.structured_output import ToolStrategy
from langchain.messages import AIMessage
from langchain_core.language_models.fake_chat_models import GenericFakeChatModel
from pydantic import BaseModel

class Scripted(GenericFakeChatModel):
    def bind_tools(self, tools, **kwargs):
        return self

class Ticket(BaseModel):
    """A support ticket."""
    priority: str

reply = AIMessage(content="", tool_calls=[
    {"name": "Ticket", "args": {"priority": "high"}, "id": "1", "type": "tool_call"},
])

agent = create_agent(
    Scripted(messages=iter([reply])),
    tools=[],
    response_format=ToolStrategy(Ticket),
)

result = agent.invoke({"messages": [{"role": "user", "content": "Server down"}]})
assert result["structured_response"] == Ticket(priority="high")
```

### Choose among several shapes

`ToolStrategy` accepts a union, so the model selects which result fits.

```py
agent = create_agent(model, tools=[], response_format=ToolStrategy(Refund | Escalation))
```

### Control error handling

```py
ToolStrategy(Ticket, handle_errors="Return a valid priority: low, medium or high.")
ToolStrategy(Ticket, handle_errors=False)
```

## Patterns and best practices

- Describe fields clearly, since descriptions are part of the prompt.
- Add constraints in the schema, then re-check business rules in code.
- Use `Literal` or enums for categories.
- Keep schemas small and shallow.

## Alternatives and trade-offs

| Option | Strength | Trade-off |
| --- | --- | --- |
| `ProviderStrategy` | Strongest enforcement | Provider support varies |
| `ToolStrategy` | Broad compatibility, retries | Extra tokens |
| `with_structured_output` | Simple, no agent needed | Fewer agent features |
| Output parser in a chain | Works on plain text | No automatic correction |

## Common mistakes

**Treating valid structure as correct content.** A schema verifies shape, not truth.

**Passing a raw JSON Schema without a strategy.** Dictionaries aren't auto-detected.

**Omitting `title` and `description` from JSON Schema with `ProviderStrategy`.** Both are required at the top level.

**Using a very deep schema.** Models get less reliable as schemas grow.

## Interview questions

<Question q="How does ToolStrategy produce structured output?">
It presents the schema as a tool, then validates the model's tool-call arguments against the schema.
</Question>

<Question q="Does structured output guarantee correct data?">
No. It guarantees shape at best. Facts still need verification.
</Question>

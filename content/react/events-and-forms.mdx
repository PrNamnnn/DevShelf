## What it is

React attaches event handlers through props such as `onClick`. A **controlled** input takes its value from state. An **uncontrolled** input keeps its own value in the DOM.

## Why it exists

Declarative handlers keep behaviour beside markup. Controlling inputs lets React validate, format or synchronize a value on every keystroke.

## How it works

Handlers receive a synthetic event that wraps the browser event. All events propagate in React except `onScroll`. Add `Capture` to a name, such as `onClickCapture`, to run on the way down.

## Syntax and key APIs

```jsx
<button onClick={handleClick}>Save</button>
<input value={name} onChange={(e) => setName(e.target.value)} />
<input type="checkbox" checked={on} onChange={(e) => setOn(e.target.checked)} />
<input defaultValue="start" />
<form action={submitAction}>...</form>
const { pending, data } = useFormStatus();
```

Name handlers `handleX`, and handler props `onX`.

## Simple example

```jsx
function Signup() {
  const [email, setEmail] = useState("");
  const valid = email.includes("@");

  function handleSubmit(event) {
    event.preventDefault();
    if (valid) register(email);
  }

  return (
    <form onSubmit={handleSubmit}>
      <input value={email} onChange={(e) => setEmail(e.target.value)} />
      <button disabled={!valid}>Join</button>
    </form>
  );
}
```

## Industry examples

### One handler for many fields

```jsx
function Profile() {
  const [form, setForm] = useState({ first: "", last: "" });

  function handleChange(event) {
    const { name, value } = event.target;
    setForm((current) => ({ ...current, [name]: value }));
  }

  return (
    <>
      <input name="first" value={form.first} onChange={handleChange} />
      <input name="last" value={form.last} onChange={handleChange} />
    </>
  );
}
```

### Read a form on submit

Uncontrolled inputs avoid a render per keystroke.

```jsx
function Search({ onSearch }) {
  function handleSubmit(event) {
    event.preventDefault();
    onSearch(new FormData(event.currentTarget).get("q"));
  }
  return (
    <form onSubmit={handleSubmit}>
      <input name="q" defaultValue="" />
    </form>
  );
}
```

### A pending-aware submit button

`useFormStatus` must be called from a component rendered inside the `<form>`.

```jsx
import { useFormStatus } from "react-dom";

function SubmitButton() {
  const { pending } = useFormStatus();
  return <button disabled={pending}>{pending ? "Saving…" : "Save"}</button>;
}
```

## Patterns and best practices

- Use controlled inputs when you react to each change.
- Use uncontrolled inputs and `FormData` for simple submit-only forms.
- Provide `''` rather than `undefined` as an initial value.
- Associate each input with a `<label>`.

## Alternatives and trade-offs

| Approach | Good for | Trade-off |
| --- | --- | --- |
| Controlled | Live validation | Renders on each key |
| Uncontrolled | Simple forms | Less immediate control |
| Form library | Large forms | Dependency |
| Action with `useActionState` | Server submissions | React 19 model to learn |

## Common mistakes

**Calling a handler during render.** `onClick={save()}` runs immediately. Pass `save`.

**`value` without `onChange`.** The field is read-only and React warns.

**Switching from undefined to a string.** An input can't change between uncontrolled and controlled.

**Reading `e.target.value` on a checkbox.** Use `e.target.checked`.

## Interview questions

<Question q="Controlled versus uncontrolled?">
A controlled input's value is driven by React state. An uncontrolled input keeps its state in the DOM and is read through a ref or form data.
</Question>

<Question q="stopPropagation versus preventDefault?">
`stopPropagation` stops the event moving to parents. `preventDefault` stops the browser's default action. They're unrelated.
</Question>

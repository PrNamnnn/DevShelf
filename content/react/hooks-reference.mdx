## What it is

Hooks are functions that let components use React features such as state and effects.

## Why it exists

Before Hooks, stateful logic was tied to class lifecycles and hard to share. Hooks compose as ordinary function calls.

## How it works

React stores each component's Hook state in an ordered list and matches calls by **position**. That's why Hooks must be called in the same order on every render.

Only call Hooks at the top level of components or custom Hooks. `use` is the exception and can be called conditionally.

## Syntax and key APIs

| Group | Hooks |
| --- | --- |
| State | `useState`, `useReducer`, `useOptimistic` |
| Context | `useContext` |
| Refs | `useRef`, `useImperativeHandle` |
| Effects | `useEffect`, `useLayoutEffect`, `useInsertionEffect`, `useEffectEvent` |
| Performance | `useMemo`, `useCallback`, `useTransition`, `useDeferredValue` |
| Other | `useId`, `useDebugValue`, `useSyncExternalStore`, `useActionState` |
| React DOM | `useFormStatus` |

| Effect Hook | Fires |
| --- | --- |
| `useInsertionEffect` | Before DOM changes, for CSS-in-JS libraries |
| `useLayoutEffect` | Before the browser repaints |
| `useEffect` | After paint, usually |

## Simple example

`useId` creates IDs that match between server and client. It isn't for list keys.

```jsx
function Field({ label }) {
  const id = useId();
  return (
    <>
      <label htmlFor={id}>{label}</label>
      <input id={id} />
    </>
  );
}
```

## Industry examples

### Measure before paint

`useLayoutEffect` blocks painting, so use it only when you must avoid a visible flicker.

```jsx
function Tooltip({ anchor }) {
  const ref = useRef(null);
  const [top, setTop] = useState(0);

  useLayoutEffect(() => {
    setTop(anchor.bottom + ref.current.offsetHeight);
  }, [anchor]);

  return <div ref={ref} style={{ top }} />;
}
```

### Expose a narrow imperative API

Don't overuse this. Prefer a prop like `isOpen` when it can express the same thing.

```jsx
function VideoPlayer({ src, ref }) {
  const video = useRef(null);

  useImperativeHandle(ref, () => ({
    play: () => video.current.play(),
  }), []);

  return <video ref={video} src={src} />;
}
```

### Label a custom Hook in DevTools

```jsx
function useOnline() {
  const online = useSyncExternalStore(subscribe, getSnapshot);
  useDebugValue(online ? "Online" : "Offline");
  return online;
}
```

## Patterns and best practices

- Enable the Hooks ESLint rules.
- Prefer `useEffect`, and use `useLayoutEffect` only for measurement.
- Reach for the "Other" group mainly when writing libraries.
- Extract repeated Hook combinations into custom Hooks.

## Alternatives and trade-offs

| Need | Hook | Instead of |
| --- | --- | --- |
| Value not affecting output | `useRef` | `useState` |
| Complex transitions | `useReducer` | Many `useState` calls |
| Subscribe to outside data | `useSyncExternalStore` | `useEffect` with `setState` |

## Common mistakes

**Calling a Hook in a condition or loop.** Slots misalign.

**Using `useId` for keys.** List keys must come from data.

**Calling Hooks after an early return.** That's also conditional.

**`useLayoutEffect` for ordinary work.** It can hurt performance.

## Interview questions

<Question q="Why can't Hooks be called conditionally?">
React identifies each Hook by its call order, so order must be identical on every render.
</Question>

<Question q="useEffect versus useLayoutEffect?">
`useLayoutEffect` runs before paint and blocks it. `useEffect` generally runs afterwards.
</Question>

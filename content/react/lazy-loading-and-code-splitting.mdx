## What it is

`lazy` delays loading a component's code until it first renders. Bundlers split each dynamic `import()` into a separate file.

## Why it exists

JavaScript has to be downloaded, parsed and executed before a page is interactive. Rarely used features shouldn't delay everyone.

If the load fails, React throws to the nearest error boundary.

## Syntax and key APIs

```jsx
const Settings = lazy(() => import("./Settings"));

<ErrorBoundary fallback={<LoadFailed />}>
  <Suspense fallback={<PageSkeleton />}>
    <Settings />
  </Suspense>
</ErrorBoundary>
```

## Simple example

```jsx
const Editor = lazy(() => import("./Editor"));

function Page() {
  const [editing, setEditing] = useState(false);
  return (
    <>
      <button onClick={() => setEditing(true)}>Edit</button>
      {editing && (
        <Suspense fallback={<p>Loading editor…</p>}>
          <Editor />
        </Suspense>
      )}
    </>
  );
}
```

## Industry examples

### Named exports

`lazy` needs a default export. Adapt a named one.

```jsx
const Chart = lazy(() =>
  import("./charts").then((module) => ({ default: module.Chart })),
);
```

### Start the download early

Calling the import on hover gives the bundle a head start, and the module cache reuses it.

```jsx
const loadSettings = () => import("./Settings");
const Settings = lazy(loadSettings);

<a href="/settings" onMouseEnter={loadSettings}>Settings</a>
```

### Keep the old UI during navigation

A Transition prevents visible content from being replaced by a fallback.

```jsx
startTransition(() => setPage("settings"));
```

## Patterns and best practices

- Split at routes and large optional features.
- Declare `lazy` at module scope.
- Use skeletons sized like the final content.
- Inspect your bundle before and after.

## Alternatives and trade-offs

| Technique | Benefit | Cost |
| --- | --- | --- |
| Route splitting | Biggest win | Delay on navigation |
| Component splitting | Removes heavy widgets | Loading states |
| Server Components | No client code | Needs a framework |
| Eager loading | Instant interaction | Larger first load |

## Common mistakes

**Declaring `lazy` inside a component.** State resets on every render.

**Splitting tiny components.** Requests can cost more than they save.

**No error boundary.** A failed chunk crashes the tree.

**Fallback causing layout shift.** Reserve the space.

## Interview questions

It takes a function returning a dynamic import. The component suspends on first render until the module resolves.

At routes first, and then large features that many users don't open.

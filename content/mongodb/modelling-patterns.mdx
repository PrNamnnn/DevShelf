## What it is

Patterns are reusable shapes for common workloads.

| Pattern | Idea | Example |
| --- | --- | --- |
| Subset | Embed only the most used part | Latest 10 reviews on a product |
| Extended reference | Copy a few fields beside a reference | Customer name on an order |
| Computed | Store precomputed results | Rating average |
| Bucket | Group many small items per document | Sensor readings per hour |
| Outlier | Handle a few very large cases separately | A viral post's followers |
| Polymorphic | Varied shapes share a collection | Different product types |

## Why it exists

Applying one general shape everywhere leads either to oversized documents or too many joins.

## How it works

Each pattern exchanges something: faster reads for more complicated writes, or duplication for fewer lookups. Choose based on measured read and write ratios.

## Syntax and key APIs

Computed update on every new rating:

```text
{ $inc: { "stats.count": 1, "stats.sum": rating } }
```

## Simple example

```js
import assert from "node:assert/strict";
import { MongoClient } from "mongodb";

const client = new MongoClient(process.env.MONGODB_URI);
const db = client.db("shelf_patterns");
await db.dropDatabase();
const buckets = db.collection("readings");

for (const reading of [{ t: 1, v: 20 }, { t: 2, v: 22 }, { t: 3, v: 24 }]) {
  await buckets.updateOne(
    { sensor: "s1", hour: "2026-01-05T10", count: { $lt: 2 } },
    { $push: { readings: reading }, $inc: { count: 1, sum: reading.v } },
    { upsert: true },
  );
}

const docs = await buckets.find({ sensor: "s1" }).sort({ _id: 1 }).toArray();
assert.deepEqual(docs.map((d) => d.count), [2, 1]);
assert.equal(docs[0].sum, 42);

await db.dropDatabase();
await client.close();
```

Each document caps at two readings here, so the third reading opens a new bucket.

## Industry examples

IoT platforms bucket by time, and product pages combine subset and computed patterns. MongoDB's time series collections provide built-in bucketing.

## Patterns and best practices

- Apply a pattern only after identifying a real need.
- Document which field is the source of truth.
- Refresh computed values with a job when eventual consistency is acceptable.

## Alternatives and trade-offs

A materialized view through `$merge` provides computed results without touching the write path. A warehouse may be a better location for heavy analytics.

## Common mistakes

- Using several patterns where one would do.
- Forgetting to update duplicated values.
- Bucketing without a cap.
- Treating an outlier case as the design center.
